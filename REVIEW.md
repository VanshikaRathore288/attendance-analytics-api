# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `/health` | Always returned 200 without pinging MongoDB or verifying index readiness. | Stop or break MongoDB; `/health` still responded `{"status": "ok"}` with 200 instead of 503. | Added `client.admin.command("ping")` and `ensure_indexes()`; catches exceptions and raises HTTP 503 `database unavailable`. |
| 2 | Global config / `load_dotenv` | Defaulted to local URI without respecting existing process environment variables. | Setting `MONGO_URI` in shell environment got overwritten by `.env`. | Used `load_dotenv(override=False)` so process environment variables strictly take precedence. |
| 3 | MongoClient initialization | Lacked `tz_aware=True` and `serverSelectionTimeoutMS`. | Stored datetimes became timezone-naive UTC; connection timeouts hung indefinitely instead of failing fast. | Initialized `MongoClient(MONGO_URI, tz_aware=True, serverSelectionTimeoutMS=3000)`. |
| 4 | Startup index creation | No indexes existed at application startup; writes relied on manual checks. | Duplicate employee codes or duplicate daily punches succeeded under concurrent load. | Added idempotent `ensure_indexes()` creating unique indexes on `employees.emp_code` and `attendance_logs (emp_code, date)` plus sort/filter compound indexes. |
| 5 | `compute_late_minutes` | Used imprecise minute comparison (`> 10`), lacked shift datetime normalization across midnight, and ignored IST time zone. | A punch-in exactly 10 minutes and 1 second late was not marked late; overnight shift punch-ins computed negative or invalid lateness. | Calculated duration against IST shift start bound; if `late_seconds > 600`, return `int(late_seconds // 60)` else 0. |
| 6 | `compute_work_hours` | Used built-in Python `round()` which performs Banker's rounding (round-half-to-even). | 4.125 became 4.12 instead of 4.13, causing discrepancies against expected half-up calculations. | Replaced with `Decimal(seconds) / Decimal(3600)` quantized with `ROUND_HALF_UP` to two decimal places. |
| 7 | `compute_overtime_minutes` | Shift end on overnight shifts failed to roll over to next calendar day; lacked 30-minute threshold check. | 25 minutes of overtime was credited; overnight shift overtime was grossly negative or miscalculated. | Constructed shift bounds with `+ timedelta(days=1)` when `shift_end <= shift_start`; only return minutes if `>= 30`, otherwise 0. |
| 8 | `punch_in` | Computed attendance date in UTC instead of IST; failed overnight early morning punches (R1); no employee existence check; check-then-insert race. | Punching in at 05:00 IST for a 22:00-06:00 shift recorded current calendar day instead of previous shift date; concurrent punches created duplicate records. | Implemented `attendance_date_for_punch` using IST bounds; validated employee existence (404); atomic `insert_one` catching `DuplicateKeyError` (409). |
| 9 | `punch_out` | Non-atomic check-then-update allowed two concurrent punch-outs to succeed; missing 24-hour interval validation. | Simultaneous punch-outs both returned 200; punch-outs days later were accepted. | Used `find_one_and_update` with filter `{"_id": doc_id, "punch_out": None}`; added validation that punch-out is between punch-in and punch-in + 24 hours. |
| 10 | `regularize_attendance` | Concurrent PATCH updates overwrote each other's audit history; allowed punches with ABSENT/LEAVE; allowed mismatched punch-in dates. | Concurrent updates lost history entries; setting LEAVE with punch times was accepted. | Added optimistic concurrency filter on `history` length and field values; enforced business rules (ABSENT/LEAVE cannot include punches, punch-in must match attendance date, change required). |
| 11 | `list_employees` | Off-by-one error `skip = page * page_size` skipped the first page; `total` count did not apply the department filter. | Requesting `page=1` skipped first 20 records; filtering by department returned total count of all employees. | Fixed skip calculation to `(page - 1) * page_size` and passed filter `q` into `count_documents(q)`. |
| 12 | `list_attendance` | Loaded all documents into Python memory, performed in-memory sort and slicing; returned `_id` instead of OpenAPI model. | OOM crashes and high latency on large collections (~100,000 records). | Replaced with database-side cursor operations: `.find(filt).sort(sort).skip(skip).limit(limit)` covered by compound indexes. |
| 13 | Pydantic Request Models | Permitted raw floats and second-based epoch integers; lacked string validations for shifts and emp_code. | Invalid employee codes like `E12` or timestamps like `1700000000` (seconds instead of ms) passed validation. | Added `StrictInt` with range validation (`100_000_000_000` to `4_102_444_800_000`), regex validations for `emp_code`, `email`, `joined_on`, and shift format checks. |

## Items Evaluated and Decided NOT to be Defects

1. **`ConfigDict(extra="ignore")` on Request Models:**
   - Kept `extra="ignore"` to allow client forward-compatibility with additional metadata without rejecting legitimate payloads.
2. **Natural String `date` (`YYYY-MM-DD`) Storage:**
   - Retained ISO date string representation rather than BSON `ISODate` for the `date` key. This preserves the natural business calendar day unambiguously without UTC timezone conversion shifting days across midnight.
3. **Empty History Representation on Attendance Documents:**
   - Legacy records without a `history` array or `half_day` field are normalized in the serialization layer to `[]` and `false` respectively, complying with the OpenAPI contract without requiring retroactive database backfills.
